# CyberHealth v2 — Release 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild CyberHealth on the v2 database so the family can log in, see and tick today's doses, view each person's medicines with history, view each person's care team, and use and edit the emergency card — with the complete Apps Script backend for those features.

**Architecture:** Unchanged pattern from v1: a no-build ES-module frontend on GitHub Pages calls one Apps Script `doPost`. Business rules are pure JavaScript with injected dependencies, tested in Node, run unchanged in a browser mock, and machine-copied into `apps-script/*.gs`. v2 replaces the date-range schedule with current-state prescriptions plus child dose rows and an append-only change log.

**Tech Stack:** Vanilla JS (ES2022 modules), CSS, Node 22 `node:test` (no npm dependencies), Google Apps Script V8, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-09-17-cyberhealth-v2-design.md`
**Database (authority for every tab and header):** `CyberHealth_Sheet_v2.xlsx`, generated by `scripts/make_template_v2.py`

## Global Constraints

- Time zone Asia/Bangkok. Dates `YYYY-MM-DD`; timestamps `YYYY-MM-DD HH:mm`.
- **Time of day values exactly:** `Morning`, `Noon`, `Evening`, `Bedtime` (Title Case, as in the Sheet's Lists tab). Order: Morning, Noon, Evening, Bedtime.
- **Frequency values exactly:** `Daily`, `Every N days`, `Weekdays`, `As needed`. **Status:** `Active`, `Stopped`. **Access:** `View`, `Edit`. **Sections:** `Medicines`, `Care team`. **Role:** `Primary`, `Family`. **DoseLog status:** `Taken`, `Skipped`.
- Column names are exactly those in `scripts/make_template_v2.py`. The server finds columns by header name.
- Access: a viewer reads a person's section if they are that person or a Sharing row for (owner, section) has `shared_with_user_id` equal to the viewer or blank; `Edit` access adds write. **Ticking is owner-only.** Libraries (Medicines, Hospitals, Doctors, DoctorHospitals) are readable by every logged-in user. Emergency cards are readable by every logged-in user, with HN only where the viewer can read that person's `Care team`; `publicEmergency` never includes HN.
- New ids: `ctx.newId(prefix)` → `<prefix>-` plus 8 random lowercase letters/digits. Hand-typed ids are accepted.
- `SheetDb.append` and the in-memory db throw on a field whose column does not exist.
- Error codes: `AUTH_REQUIRED`, `AUTH_FAILED`, `LOCKED_OUT`, `FORBIDDEN`, `NOT_DUE`, `FUTURE_DATE`, `BAD_INPUT`, `CONFLICT`, `SERVER`. Messages plain English, active voice, saying what to do next.
- Files synced to Apps Script (`js/schedule.js`, `js/access.js`, `js/authcore.js`, `server/actions.js`): one import per line, no DOM/Node APIs, unique top-level names across all synced and `apps-script/*.gs` files, no top-level code using another file's names. Run `npm run sync-gs` and commit the generated files.
- Every Sheet value reaching HTML goes through `esc()`. Tap targets ≥ 44px. No horizontal overflow at 390px or 320px.
- `js/config.js` ships `API_URL = ""`. `"mock"` works only when the page is not served over https.
- No npm dependencies. Commit messages end with:
  `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`

### Task 2: Scheduling rules for prescriptions

**Files:**
- Create: `js/schedule.js`, `tests/schedule.test.js`

**Interfaces — produces (all exported):**
- Constants: `TIMES_OF_DAY = ["Morning","Noon","Evening","Bedtime"]`, `FREQ = {DAILY:"Daily", EVERY_N:"Every N days", WEEKDAYS:"Weekdays", AS_NEEDED:"As needed"}`, `WEEKDAYS = ["Mon","Tue","Wed","Thu","Fri","Sat","Sun"]`.
- Date helpers, salvaged from `phase-2:js/schedule.js`: `parseDate`, `addDays`, `daysBetween`, `weekdayOf`, `bangkokToday`, `bangkokStamp`, `bangkokHour`. Plus `timeOfDayAtHour(hour)` (<11 Morning, <16 Noon, <20 Evening, else Bedtime) and `bangkokTimeOfDay(nowMs)`.
- `normalizePrescription(row) → {ok:true, prescription} | {ok:false, id, reason}` where prescription is `{id, userId, medicineId, freq, n, days:string[], countFrom, meal, doctorId, status, startedOn, notes}`. Rejects: missing `prescription_id`, `user_id` or `medicine_id`; unknown frequency; `started_on` not a date; `Every N days` without a whole `every_n_days` ≥ 1 or without a valid `count_from`; `Weekdays` with no valid day; status not `Active`/`Stopped`. `weekdays` is parsed from "Mon, Thu" (any case, comma or space separated). `meal_timing` blank → `"Any time"`.
- `normalizeDose(row) → {ok:true, dose} | {ok:false, id, reason}` where dose is `{id, prescriptionId, timeOfDay, amount:number, unit}`. Rejects: missing ids; time of day not one of the four; amount not > 0; unit blank.
- `isDue(prescription, date) → bool` — `status === "Active"`, `date >= startedOn`, and the frequency rule from the spec §4 (`Every N days` also needs `date >= countFrom`). `As needed` → false.
- `doseItemsOn(prescriptions, doses, date) → [{key, date, timeOfDay, prescription, dose}]` — one item per dose row of every prescription due that date, sorted by `TIMES_OF_DAY` order then by input order. `key = "<date>|<timeOfDay>|<prescriptionId>"`.
- `doseKey(date, timeOfDay, prescriptionId)`.
- `slotStatus({due, taken, date, today, timeOfDay, nowTimeOfDay}) → "none"|"done"|"missed"|"now"|"upcoming"` — same rules as v1's `slotStatus` with times of day.
- `lastChangeDate(changes, prescriptionId) → date | ""` — the date part of the latest `changed_at` among that prescription's changes.
- `countsOnDay(prescription, changes, date) → bool` — `lastChangeDate` is blank or `<= date`.
- `describeFrequency(prescription)` — as v1: "Every day", "Every other day", "Every 3 weeks", "Every Wed", "Mon + Thu", "When needed".
- `describeDoses(doses) → "Morning 1 tablet · Evening 2 tablets"` in time-of-day order; `"When needed"` for none.
